### Gespeicherte Daten und Modulverdrahtung (aus Architecture)

- Folders (by domain): `Locales/`, `Core/` (core events/lifecycle, database, profiles, client detection, commands, debug), `Lib/` (domain-free helpers: Format, Serializer, ChatPatterns, Bags, Items, Widgets, Charts, Export), `Tracking/` (counters and event producers), `History/` (history, journal-based evaluation, forecast, goal), `Speedrun/` (runs, splits, records, split list and views), `Assist/` (comfort automation, reminders, warnings, declines), `UI/` (windows, stat lines, alerts, options). Load order in the `.toc` is the dependency order, independent of folders. Moving files changes the `.toc`: client restart needed; the installer removes the old paths via its manifest.
- `LevelTimerDB` (account): settings, exposed as `ns.db` (always the active settings). `Profiles.lua` keeps named copies in `LevelTimerDB.profiles`, the active name in `activeProfile` and each character's choice in `characterProfiles`; switching/logout writes the active settings back into the active profile, login loads the character's profile before the first apply. New settings need nothing extra (profiles copy every key except the profile meta keys; missing ones get defaults). Has its own `schemaVersion` and `settingsMigrations` (v2: old `fontSize` -> `scale`).
- `Database.Load` migrates and fills defaults for every stored character, not only the logged-in one; `migrate` never lowers `schemaVersion`. A saved level above `UnitLevel` means the name was reused by a new character: `Database.OnCharacterReplaced` (Runs keeps the old attempt as an imported run), then the data starts fresh. Test fixtures for other characters need `schemaVersion = addon.Database.CHARACTER_SCHEMA_VERSION`, otherwise they are migrated as v1 data. Imported profiles go through `Database.SanitizeSettings`.
- `LevelTimerStatsDB` (account): `characters["Name-Realm"]` = `{ schemaVersion, name, realm, class, currentLevel, currentSession, levelHistory, sessionHistory }`. The logged-in character is `ns.character`, its key `ns.characterKey`. Account-wide so the history can show and compare every character.
- `LevelTimerCharDB` (per character): legacy. Still declared in the `.toc` only so old data loads; on login it is moved into `LevelTimerStatsDB` and set to nil.

Data modules without UI: `Stats.lua` (counters per scope), `PlayedTime.lua`, `Session.lua`, `Experience.lua`, producers `KillCounter.lua`, `DeathCounter.lua`, `QuestCounter.lua`, `MoneyCounter.lua`, then `History.lua` (records, `DeathCauseText`) , `Analysis.lua` (chart series) and `XpTable.lua` (XP per level from warcraft.wiki.gg: 1.12 values for Classic Era/Forever, post-2.3 values for TBC, none for Retail; only trusted when `values[ns.level] == UnitXPMax`; `XpBetween(from, to)`), `Forecast.lua` (`SecondsToLevel(target)`/`SecondsToMaxLevel`: rest of current level like the level ETA, then the remaining levels' XP from `XpTable` divided by the XP/h of the last 5 finished levels plus the current one; without a table the average time of the last 5 levels per remaining level), `Runs.lua` (runs = own characters' level times plus imported runs, favorites; `Runs.GetAll/Get/FindByName/LevelTimes`), `Splits.lua` (reference times per level from setting `splitComparison`: `best` per level, `pb` = fastest other run up to the current level, `run` = `db.splitReference = { id, name, times }`, copied when chosen (`Splits.SetReferenceRun`, `/lt compare Name`) so it stays fixed; cached per comparison/level/character count; `GetCurrentDelta`/`GetLevelDelta`/`GetTotalDelta`), `WorldRecords.lua` (compares `/played` when reaching the bracket level, from `levelHistory[level-1].totalPlayed`, or the running `/played` before that, with the record; setting `worldRecordScope` = overall/class), `Goal.lua` (target level per character in `character.goal`, progress in level fractions, `/lt goal 30`).

UI: `StatLines.lua` (`ns.STAT_LINES`, the single list of stats: `{ setting, label, rows = { { label, value(scope) } } }`; the window renders each row as label left / value right, options generate one toggle per stat), `LevelUpSummary.lua` (chat line in `OnLevelCompleted`, setting `levelUpSummary`; optional announcement to party/instance chat or guild via `levelUpAnnounce`, no /say (needs a hardware event outdoors; settings migration v4 turns old `say` off), sent with `C_ChatInfo.SendChatMessage` (fallback `SendChatMessage`), skipped during `C_ChatInfo.InChatMessagingLockdown()`), `TimerWindow.lua`, `Charts.lua`, `HistoryWindow.lua`, `HistoryTables.lua`, `HistoryCharts.lua`, `RecapWindow.lua` (`/lt recap`: session summary card, `RecapWindow.BuildRows()`, journal entries filtered by `currentSession.startedAt`), `MinimapButton.lua`, `Options.lua`, `Commands.lua`.
- Session = login to logout. `OnLogout` stores `seconds` and `lastSeen`; on the next login a gap ≤ `RESUME_GAP_SECONDS` (reload, disconnect) resumes it, otherwise it is archived to `sessionHistory` (if ≥ `MIN_ARCHIVED_SECONDS`, capped at `MAX_ARCHIVED_SESSIONS`) and a new one starts. Archiving happens at login because at logout a reload can't be told apart from a real logout. `Session.StartNew()` (`/lt newsession`, settings button, via `ns.StartNewSession`) closes and archives the running session immediately and starts a new one.

### v2.23 quality notes

- Test stub: scenarios `era_*` load as Classic Era (11509), `forever_*` as Forever (16001), others Retail.
- `Format` reads unit strings at call time (`UNIT_DAY/HOUR/MINUTE/SECOND/THOUSAND/MILLION/GOLD/SILVER/COPPER_SHORT`); never hardcode "d/h/m/s/k/M/g". `L.FULL_DATE_FORMAT`; `WorldRecords.GetFetchedText()/GetFetchedAt()`.
- `Experience.XpMaxOf(level)` = XP requirement of a level as last seen; use it in `OnLevelCompleted` instead of `UnitXPMax`. `PlayedTime.Sync(onAnswer)` optional one-shot callback `(total, thisLevel)`.
- `ns.UndoStatPreset()` (rows kept in `db.presetBackup`); `ns.ConfirmProfileDelete(name)`, `ns.ConfirmProfileSave(name, onSaved)`, `Profiles.CanDelete(name)`.
- `TableView` optional `rowLink(record)` (game tooltip); running `isCurrent` row replaced in place without re-sort when no filter/sort. `createChartView(tab, kind, data, axis, revision)` recomputes journal charts only on revision change. History window re-renders only the selected view each second; `History.GetInstanceLog` returns a cached list (don't mutate). `Classification.Of(name)` prefers the dead target with that name. Near deaths tab only where `NearDeath.IsAvailable()`.
- Line endings: repo files are LF. Agents on Windows must not convert to CRLF (a CRLF branch conflicts on every line when merged).
