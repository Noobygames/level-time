### Build, Installer, Release (aus Build / test / run)

- `make package`: installer tool in `-package` mode writes `dist/LevelTimer-<version>.zip` (folder `LevelTimer/` with the `.toc` files, everything under `Media/` and `LICENSE`, see `assetDirs` and `packageExtras`). The Level Time zip also contains `LevelTimer_Archive/` (`-addons LevelTimer,LevelTimer_Archive`; several addons = one zip); the CurseForge packager moves that folder to the top level via `.pkgmeta` `move-folders`.
- Assets: textures live in `Media/` (not listed in the `.toc`; installer and package pick up `assetDirs` automatically). Use TGA (32-bit, power-of-two sizes); PNG is not reliably loaded by all clients. Reference them without extension via `Widgets.ICON`-style paths built from `addonName`.
- `make records`: `tools/records` fetches the fastest runs from the speedrun.com API (WoW Classic: Leveling, SSF, Softcore; brackets 1-10/1-20/1-60, overall and per class) and rewrites `Speedrun/SpeedrunRecords.lua` (`ns.SpeedrunRecordsData`, generated, don't edit by hand). The addon has no network access, so the data ships as a snapshot; `make test` runs the tool's tests offline (httptest).
- `make artwork`: `tools/artwork` renders the CurseForge logo (`curseforge/logo.png`) and the addon icon (`Media/Icon.tga`, used by the minimap button and `## IconTexture`) from one drawing in `draw.go`. Regenerate both after changing it; no Blizzard assets allowed (CurseForge rule).
- Release names: zip and CurseForge label are `LevelTimer-v<version>(.zip)` (packager `-n` in `release.yml`), matching the earlier manual uploads; keep it that way.
- Release: pushing a tag `v*` runs `.github/workflows/release.yml` (tests, then BigWigs packager: zip, GitHub release with both zips (Level Time Goals attached via `gh release upload` from `sg-repo/.release`), uploads to CurseForge / Wago / WoWInterface for each platform whose `.toc` ID (`## X-Curse-Project-ID`, `## X-Wago-ID`, `## X-WoWI-ID`) and secret (`CF_API_KEY`, `WAGO_API_TOKEN`, `WOWI_API_TOKEN`) both exist). The packager ships the repo minus `.pkgmeta` `ignore`, so new non-addon files must be added there. CurseForge listing texts and logo live in `curseforge/`.
- The installer copies the files listed in the `.toc` (plus the `.toc`) into `<WoW>/_<flavor>_/Interface/AddOns/<TocName>/`. The folder name must match the `.toc` filename (`LevelTimer`), not the repo name. It writes `.install-manifest.json` there to track owned files; files removed from the `.toc` get deleted on the next install.
- Installer never touches `WTF/` (SavedVariables), enforced in `ensureNotConfigPath`. Install-layout migrations live in `tools/installer/migrate.go` (IDs recorded in the manifest, run once); SavedVariables migrations belong in the Lua code (`Database.lua`).

### Build / test / run

No build step or linter. The game client loads `.lua` files directly.
- `make test`: runs addon scenarios and installer tests. `make test-addon` only the Lua scenarios; single scenario: `go -C tools/addontest test -count=1 -run 'TestScenarios/session' ./...`. Always pass `-count=1`: Go doesn't track the Lua files and would show stale cached results.
- Addon tests: `tools/addontest` (Go + gopher-lua, Lua 5.1 like the client) runs every `tests/*_test.lua` in a fresh Lua state. `tests/wow_stub.lua` fakes the WoW API (frames, events, unit/XP/money/clock functions), loads the addon in `.toc` order and provides `wow.login/logout/fire/advance/levelUp/click/state`, `addon` (= `ns`) and `expect/expectNear/expectTrue`. Unknown frame methods are no-ops; add API functions to the stub when the addon starts using them. `C_Timer.After` callbacks are queued and only run on `wow.runTimers()`. New feature = new or extended scenario.
- The stub only checks logic, not rendering or real API availability per client; in-game testing is still needed.
- `make install`: interactive wizard (pick WoW flavors, review plan, confirm). `make update`: same without prompts, updates already installed flavors. `make dry-run`: show plan only. Extra flags via `ARGS="-flavors retail,classic_era -wow 'D:/Games/World of Warcraft'"`; `WOW_DIR` env also works.
- `make test-installer` / `make vet`; single installer test: `go -C tools/installer test -run TestParseSelection ./...`.
- `make package` / release / installer / `make records` / `make artwork`: see `docs/notes/build-release.md`. Basics: `make package` writes `dist/LevelTimer-<version>.zip` (everything under `Media/`, `.toc` files, `LICENSE`); assets are TGA (32-bit, power-of-two) in `Media/`, not listed in the `.toc`, referenced without extension; zip and CurseForge label are `LevelTimer-v<version>`; pushing a tag `v*` releases; the packager ships the repo minus `.pkgmeta` `ignore`, so new non-addon files (docs, notes) must be added there; the installer copies the `.toc` file list into `<WoW>/_<flavor>_/Interface/AddOns/<TocName>/`, folder name = `.toc` name, and never touches `WTF/`.
- `## Version: @project-version@` in the `.toc` is replaced with the version on install and package (`Addon.ReadFile`) and by the CurseForge packager. Always read addon files through `Addon.ReadFile`, never raw.
- CI: `.github/workflows/test.yml` runs `make vet` and `make test` on every PR and push to `main`.
- Reload after changes: `/reload` in game; `.toc` changes (new files, SavedVariables) need a client restart. Lua errors only show in game (enable `/console scriptErrors 1` or use BugSack).
- In-game commands: `/lt` or `/leveltimer` (no args opens settings) with `config | history | lock | unlock | reset | compact | bar | newsession | recap | copy | splits | stream | goal | compare | runs | profile | sync | show | hide | minimap | debug | edit | report | welcome | help [all]` (full list and `/lt debug ...` subcommands in `docs/notes/debug.md`).
- Logging: call `ns.Debug(area, "... %s", value)` at decision points (only `%s`, values are converted, secrets shown as `<secret>`); debug lines are technical English and not localized, `ns.DebugPrint` prints regardless of the flag (test command output).
- Debug log: `/lt debug log` (persists across /reload; `clear`, `status`), `/lt debug check` (runs `DebugLog.AddCheck` checks once), `make debuglog` prints the saved lines as JSON Lines. Collection lives in `Core/DebugLog.lua`, `Core/DebugProbes.lua` (event probes, snapshots), `Core/DebugChecks.lua`; details in `docs/notes/debug.md`. New open in-game question = add a `CHECKS` entry or an event probe (name `<roadmap>.<area>.<what>`, add it to the `CHECKS` lists of scenarios `debug_checks`, `era_debug_checks`, `forever_debug_checks` and to ManualToCheck "Per Debug-Log abgedeckt") instead of asking for `/dump`. `ns.Print` lines also go to the log; debug-only preparation behind `ns.DebugActive()`.

### make locale (tools/locale)

`make locale ARGS="-file /abs/path/texts.json"` schreibt Texte in `Locales/deDE.lua`, `enUS.lua`, `frFR.lua`, `esES.lua`, ohne dass man sie lesen muss (je ~125 KB). `ARGS="-remove KEY1,KEY2"` loescht Schluessel aus allen vier. Eingabe (JSON, Klartext, `
` fuer Zeilenumbruch, Anfuehrungszeichen und Backslashes escapt das Werkzeug): `{ "KEY": { "deDE": "...", "enUS": "...", "frFR": "...", "esES": "..." } }`. Vorhandene Schluessel werden ersetzt, neue vor der schliessenden Klammer angehaengt. Fehler (nichts wird geschrieben): fehlende oder unbekannte Sprache, `%s/%d` in anderer Reihenfolge als enUS, ungueltiger Schluessel (`A-Z0-9_`). Pfad zur JSON-Datei absolut angeben (das Werkzeug laeuft mit `go -C tools/locale`). Tests: `make test-locale`.
